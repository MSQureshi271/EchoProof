# P2-03 audit configuration and contracts

`configs/phase2.yaml` configures the audit independently of the Phase 1 fixture settings. `echoproof.phase2_config.load_phase2_config` validates the file without scanning or creating source directories. Paths are project-relative and source/output overlaps are rejected. Capacities are unknown by default; `require_acquisition_capacity` blocks acquisition unless both capacities and the acquisition ceiling cover the requested bytes. Decode limits are audit resource limits, not dataset eligibility decisions.

`echoproof.data.audit_contracts` defines file inventory, provenance, mapping evidence, pair relationships, dispositions and reconciliation records. They provide JSON round trips through the existing `Metadata` interface. Unknown fields use null; inventory entries without a SHA-256 remain inventory entries and must not be converted into `Recording` objects with invented hashes. `validate_scope` rejects mixed fixture and research audit rows, and scoped endpoint IDs reject fixture IDs in research records. Future adapters must call it when constructing collections. These records do not grant admission: permissions, language and identity evidence remain separate requirements.
