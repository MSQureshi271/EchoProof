# P1-06 reproducibility and artifact records

Run `python -m echoproof.cli doctor --config configs/phase1.yaml` to print the selected runtime inventory. Run `python -m echoproof.cli storage-probe --config configs/phase1.yaml` to create a unique directory under the configured Drive `runs/phase1` path. Both accept `--project-root`, `--run-root` and `--device` like `validate-config`. These are fixture software checks; no recordings are opened.

Each successful storage probe writes `resolved_config.yaml`, `environment.json`, `events.jsonl`, `metrics.json`, `artifact_manifest.json`, and finally `status.json`. The manifest hashes the first four files. A fresh Python process verifies those hashes before success is written; `status.json` records the manifest hash and verification count. This proves readback in a separate process in that session, not recovery after a Colab restart or a remote backup. A failed run can leave an incomplete directory; an absent or invalid status is not success. The writer reserves each name exclusively and uses a flushed temporary file and `os.replace` in the same directory. It refuses overwrites. Cloud Drive filesystem behavior and power-loss durability must be checked on the actual mount.

Config hashing uses canonical UTF-8 JSON with sorted keys, compact separators and nonfinite numbers rejected. It hashes all resolved config fields, including resolved paths; equivalent relative and absolute settings resolve to the same path on a given machine, while a different machine or project path can change the hash. Run IDs, timestamps, runtime information and metrics are not config fields and are excluded. `contract_source_sha256` hashes the current contracts source file; it is source provenance rather than a semantic schema hash. The environment records source revision only when available; no dependency lock is claimed until P1-13.

Named seeds derive from SHA-256 and are recorded for global, fixture, crop, augmentation and loader streams. The smoke check compares two fresh CPU processes at exact tolerance for their short Python, NumPy, PyTorch and zero-worker loader outputs. Deterministic PyTorch mode is enabled, but unsupported operations can raise; this smoke check does not prove reproducibility across hardware, releases, CUDA operations, or worker processes. `seed_worker` supplies a future worker callback, and multiworker verification is required before using workers. Configured precision and actual probe precision are recorded separately.

Never log audio bytes, transcripts, credentials, or arbitrary environment variables. Run path and source details are still environment metadata; review before sharing. Future training checkpoint resume must save and validate model, optimizer, scheduler, AMP scaler, epoch/step, RNG, sampler/data position and config/split hashes. It must refuse mismatches unless a new run is explicitly started. This task does not implement checkpoint resume.
