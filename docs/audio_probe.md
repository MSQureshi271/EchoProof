# P1-07 generated audio probe

`python -m echoproof.cli fixtures create --config configs/phase1.yaml` creates a unique directory below the configured fixture root. The manifest records the generator version, seed, named seed and SHA-256 for every generated file. The waveforms are artificial signals for testing software, not examples of human or TTS speech. Generated files and existing fixture runs are preserved; rerunning creates a new directory.

`python -m echoproof.cli probe audio --config configs/phase1.yaml` generates its own registered fixture runs and checks WAV decoding, metadata, reproducibility, resampling, mono conversion, padding, silence detection, invalid inputs and an FFmpeg MP3 round trip. It does not take an arbitrary input path. It records software-only results and FFmpeg/runtime provenance under a unique `runs/phase1/` directory with a checksum manifest and fresh-process readback. A missing or invalid success status means the run did not complete. The CLI returns structured errors on failure.

`data.audio.decode_audio` uses SoundFile to decode bounded byte input to float32, rejects empty/corrupt, truncated, nonfinite or out-of-bounds audio, averages stereo channels, and uses SciPy polyphase resampling when the source rate differs. The Phase 1 probe permits 4–384 kHz, one or two channels, 30 seconds, and 10 MB. R1-N2 reviewed them and raised the defaults to the application limits, 60 seconds and 25 MiB (`MAX_AUDIO_SECONDS`, `MAX_AUDIO_BYTES`). It does no denoising or peak normalization. `windows` covers the entire canonical waveform in nonoverlapping windows and right-pads each final short window; each tuple includes its valid sample count and start sample. Silence below RMS 0.0001 is flagged, not rejected.

The MP3 check encodes one generated second with FFmpeg/libmp3lame at 128 kbps and decodes it back with FFmpeg. It allows at most 0.08 seconds duration difference and 0.08 waveform RMS error. These are software probe tolerances, not claims about model accuracy or audio quality. Research preprocessing, segment policies, dataset admissibility and upload restrictions are finalized in later phases.
