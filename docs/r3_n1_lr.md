# R3-N1: selected LR calibration

Muneeb is taking over the LR portion of R3-N1; Usman is the plan's reviewer. The frozen development contract is `configs/r3_n1_lr_contract.json`. It identifies the selected full 67-feature R2-M1 LR, not the experimental 60-feature ablation model. Component hashes have been checked against both the verified M2 bundle and the original R2-M1 evidence.

The contract follows the plan's temperature scaling, with calibration applied to recording scores after mean chunk aggregation. Temperature is fitted on the B calibration role; the separate B operating role is used to compare calibration and choose a threshold. The proposed calibration acceptance rule, fixed before examining LR operating results, is strictly lower operating log loss with no worsening in Brier; otherwise retain uncalibrated model-score wording. This is an operational interpretation of the plan's "if calibration does not help" instruction, not a claim of generalization or an independent test.

The role-separated prediction export is implemented in `scripts/r3_n1_lr_export.py`. It verifies the original selection scores, input and model hashes, role counts and speaker separation before writing six chunk/recording prediction files and evidence. It refuses to overwrite an existing output directory. Focused role checks are in `tests/test_r3_n1_lr_export.py`.

The calibration-only fit is implemented in `scripts/r3_n1_lr_fit.py`. It checks the export evidence, selected model identity and calibration prediction checksum, checks calibration identities and coverage, and fits one temperature using only that role. The separate fit artifact records in-sample diagnostics and explicitly does not select a threshold or assess calibration acceptance. The fit requires no operating prediction file. Tests are in `tests/test_r3_n1_lr_fit.py`.

Operating evaluation is implemented in `scripts/r3_n1_lr_operating.py`. It verifies the frozen fit and source hashes, checks calibration/operating recording and speaker disjointness, compares raw and temperature scores under the predeclared acceptance rule, and selects an operating threshold with the shared tie-breaks. It writes recording predictions, a reliability plot and bins, metrics and evidence to a new directory. These are development results, not independent test performance. Synthetic tests cover the rejection fallback and group leakage; local tests use a plotting stand-in because matplotlib is not installed locally. Actual plot rendering remains to be checked in Colab.

The development handoff is implemented in `scripts/r3_n1_lr_bundle.py`: it packages the selected LR weights, score rule and operating decision rule in a new bundle and checks reloaded recording scores and decisions against the exported operating predictions. `load_lr_bundle` dispatches this bundle type to `models/r3_n1_lr_bundle.py` so accepted calibration is applied after recording aggregation; rejected calibration remains a raw model score. This parity check starts from saved recording scores; waveform-to-model parity was checked separately during R3-M2. Synthetic handoff and existing bundle regression tests pass locally. No real-data handoff has yet been created.

`notebooks/R3_N1_LR_Colab.ipynb` runs the checks, export, fit, evaluation and handoff using the verified Drive data. It verifies completed evidence before reusing an existing stage and will not overwrite incomplete stage directories.
