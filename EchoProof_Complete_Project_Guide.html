The project at a glance

Build a reproducible research pipeline that distinguishes genuine English speech from TTS-generated speech, compares four model families, and exposes the selected detector through a usable Python application.

WavLM-Base-Plus

Frozen speech encoder and a trainable classification head.

04 · ADVANCED

Fine-tuned AST

Spectrogram patches, self-attention, and task-specific adaptation.

Your selected order is preserved. There is no XGBoost experiment and no standalone CNN baseline. PHASE 0 · WEEK 1

Define the research contract

Specify the task before choosing metrics

Input: a recording containing speech. Training label: 0 = genuine, 1 = TTS. Output: a recording-level synthetic score, a thresholded prediction, quality warnings, and model/version information. A score estimates what this detector learned under its evaluation conditions; it cannot establish who spoke, whether a statement is true, or whether a file is legally authentic.

TTS includes synthesis conditioned on text, including text-based voice cloning. Voice conversion transforms an existing speech signal into another voice and is outside this project’s detection claim. Do not identify method type from a product name alone: Chatterbox TTS and Chatterbox VC are different branches. Singing, mixed human/synthetic clips, speech editing, unknown languages, and replay-only attacks remain outside the initial validated scope.

Research questionControlled comparisonEvidence to collect
Does temporal learning help?Logistic Regression vs. BiGRU on identical recordingsMacro F1, EER, errors by duration and generator

Do predictions survive distribution shift?Locked systems on a second dataset and controlled corruptionsExternal results, false positives, paired degradation

The third comparison changes both representation and training regime. Describe it as a comparison of complete approaches. Optional frozen-AST and partially fine-tuned-WavLM experiments help isolate the role of fine-tuning if time permits.

Predeclare the selection rule

Choose the production candidate using development data only: prioritize macro F1 on an unseen-generator validation challenge, then lower validation EER, then genuine false-positive rate and latency. Use in-domain validation as a sanity check. Record this rule before comparing models. Final unseen-generator and external tests assess the chosen system; using them to select a winner would turn them into validation sets.

A reasonable engineering target is a useful response within five seconds for a ten-second recording on the named demo hardware. Treat that as a target to measure. Do not promise a particular accuracy. Define success as a correct, reproducible comparison and an honest working application, including when results are modest.

Define the minimum project and optional work

Core: two documented data sources, verified labels, leakage checks, meaningful EDA, four trained approaches, one unseen-generator protocol, external evaluation, a compression/noise test, working interface, and the report. Optional: all generator rotations, three-seed repeats of every expensive run, full-backbone fine-tuning, phoneme analysis, additional languages, and ensembles. An ensemble is not necessary to demonstrate improvement; a measured tuning experiment is sufficient.

Estimate compute instead of guessing

Run 100 representative batches, measure median seconds per step and peak GPU memory, then estimate steps_per_epoch × seconds_per_step × epochs. Record extraction time separately from training time. A 12–16 GB GPU is a useful planning target, not a guarantee for every AST batch size. Begin with a batch of 2 and scale up. Reserve roughly a quarter of available GPU time for reruns and integration.

At 16 kHz, mono float32 audio uses about 16,000 × 4 = 64,000 bytes/second. Four-second crops use about 256 KB before container overhead. Cache only what saves meaningful work; long hidden-state sequences are much larger than pooled embeddings.

PHASE 2 · WEEK 1

Acquire and verify the datasets

Primary source: PhonemeDF

The official v1.0.1 record reports 28,539 real utterances and 199,773 synthetic utterances across four TTS and three VC systems, standardized to 16 kHz. It was published on 11 April 2026; its metadata lists creation during March–June 2025. Thus it is a recent release, not evidence that all generators represent October 2026 technology. [1]

KeepExcludeRole
Real / LibriSpeech-derived—Genuine class
MeloTTS, XTTS v2, Chatterbox TTS, VITSChatterbox VC, FreeVC, StarGAN VCTTS-only synthetic class

The real plus four TTS archives total approximately 41.4 GB compressed using the publisher’s rounded sizes. Allow separate space for extraction, caches, and checkpoints. The full dataset’s 730-hour figure includes VC; do not use it as the TTS-only training duration. [1]

The authors’ repository shows paired utterance/system naming and separate reference-voice audio. Use its documentation to build a verified adapter, then validate that the downloaded archives follow the same conventions. A source-speaker ID does not necessarily identify the synthesized target voice. [2]

Second source: MLAAD-tiny

The dataset card describes roughly 6,000 genuine files from M-AILABS and 6,400 synthetic files from 64 TTS systems. It also mentions English training and German testing, while the viewer exposes 15,290 rows in one split. Treat these as unresolved documentation/count differences, not a ready-made evaluation protocol. Synthetic data is described as CC BY-NC 4.0; genuine audio retains its original license. [3]

Recommended use: a sealed external English test containing both genuine and verified TTS examples. Do not trust the viewer’s single “train” label as your experimental split. Parse original metadata and count actual usable files by language, label and generator. If English genuine and TTS subsets cannot both be verified, do not publish an English-only binary result from it. Resolve metadata or replace the external benchmark before proceeding.

Acquisition procedure

  1. Save source URL, dataset version/revision, retrieval date, documentation, license text, and archive checksum. Use the exact release identifier, not “latest.”
  2. Download the documentation and a small representative sample first. Verify class, method, speaker/utterance mapping, duration and readability.
  3. Download only required archives using resumable transfer. Verify publisher checksums; also compute your own SHA-256 inventory.
  4. Extract into a read-only raw-data area using safe archive paths. Avoid flattening directories or overwriting files with repeated names.
  5. Build one dataset-specific adapter for each source, with explicit mappings and an unknown/quarantine state. Never map “not real” automatically to TTS.
  6. Produce a count reconciliation: publisher figures → downloaded files → decoded files → scope-eligible files → final retained recordings.
License and freshness gates

The PhonemeDF pages retrieved for this guide did not provide an unambiguous license in the visible text. Inspect the downloaded documentation and underlying source conditions; seek clarification before redistributing audio. For every dataset, record generator versions and synthesis dates where available. Neither a new upload date nor a long generator list proves coverage of current commercial TTS.

Keep the first experiment manageable

Begin with a 500–1,000-recording integration sample, balanced by class and spread across available groups. After the full pipeline works, consider 20,000–40,000 recordings, subject to audit and compute. Construct the sample after group splits. Select real utterances and synthetic variants so each TTS family contributes reasonably evenly; document whether paired variants are sampled or all retained.

For a strict two-dataset training requirement, reserve an MLAAD development partition before tuning and add it only in a separate mixed-source experiment. Keep a disjoint external test and include both classes from both sources in training. Otherwise the model may learn which dataset a recording came from. The default plan uses dataset two for external evaluation; the CCA brief’s wording should be clarified with the instructor if both must train the model.

Namespaced speaker IDs such as phonemedf:19 prevent collisions across corpora. Preserve missing identity values as unknown. Do not invent speaker or generator labels from guesses, listening, or automated clustering alone. Clustering can flag likely overlaps for review.

Cleaning in a fixed order

  1. Validate bytes: reject unreadable, empty or invalid decoded audio; catch exceptions and log the reason.
  2. Validate values: flag non-finite values, unexpected scaling, near-total silence, clipping and suspicious durations. Review thresholds on the training portion and apply the same policy to every class.
  3. Inspect duplicates: hash file bytes and standardized decoded PCM. Investigate near-duplicates with fingerprints or similarity. Keep one representative per exact duplicate group, or keep the group in a single partition. Conflicting labels require quarantine and investigation.
  4. Standardize: decode to floating point, apply a documented mono rule, resample once to 16 kHz, and preserve originals. Inspect stereo phase cancellation if averaging channels.
  5. Avoid destructive cleaning: default to no denoising, no pitch shift, no strong equalization and no aggressive silence removal. These can erase synthesis cues or create processing artifacts.
  6. Track exclusions: show removal counts per label, dataset and generator. A rule that disproportionately removes one class may change the task.

Missing acoustic feature values are handled later with a train-fitted imputer and, where meaningful, a missingness flag. Missing labels and ambiguous method type cannot be repaired with a numerical imputer.

Run a tiny shortcut classifier using only duration, RMS, silence fraction, codec and sample-rate metadata. A strong result is a warning that a detector may succeed without learning transferable synthesis cues. A CVPR 2025 study demonstrated leading-silence shortcuts in two audio-visual deepfake datasets; that motivates this audit but does not establish the same defect in PhonemeDF. [10]

PHASE 4 · WEEK 2

Build leakage-safe evaluation protocols

Split source groups first. Create crops and fit transformations afterward.

What belongs in the same group?

Connect all files derived from the same source utterance, duplicate audio, and augmented parents. If you promise source-speaker independence, connect every utterance from that speaker as well. For output-voice independence, also account for target voices and cloning references. These relationships can form connected components: assign each component to one partition.

Crucial limitation: a small shared target-voice pool can make source-plus-target-voice-disjoint splitting impossible or produce one huge component. Do not quietly break the constraint. Keep source-speaker and utterance independence as the core claim, report target-voice overlap, and run a separate target-voice experiment if feasible. Distinguish all three meanings of “speaker-disjoint.”

Protocol A: known-generator comparison

Target approximately 70% train, 15% validation and 15% test by source groups. Exact proportions depend on group sizes. All eligible generator families may appear in each partition, but source utterances and the declared speaker groups may not. Within validation, reserve disjoint groups for model selection, calibration and operating-threshold choice if sample size allows. Otherwise use a documented group-aware cross-fitting design.

StratifiedGroupKFold can preserve group exclusivity while attempting class balance across folds; it does not directly produce a guaranteed 70/15/15 allocation. Use group-aware assignment or nested group splits and inspect the resulting distributions. Never abandon group integrity to achieve exact percentages. [9]

Protocol B: unseen TTS generator

With four families, an example strict design is: train on MeloTTS + VITS; use XTTS v2 as the unseen-generator validation family; seal Chatterbox TTS as the final unseen family. Allocate source-speaker groups first, then filter families within each partition. Pair the held-out synthetic test recordings with genuine recordings from the test source groups. Genuine references from those same source groups must not appear in training.

This trains on fewer families than Protocol A, so report the two protocols separately. Keep the final held-out family out of all development data, including the second dataset. Generator aliases, forks and shared architecture families need an explicit overlap policy. If you cannot verify family independence, call the condition “unseen dataset system ID” rather than a proven unseen architecture.

Optional leave-one-generator-out rotation uses a fresh model per held-out family and training-run-local preprocessing. Predeclare inner validation selection and tuning budgets. Do not change hyperparameters after reading a rotation’s final test result and still call that result untouched.

Protocol C: cross-dataset transfer

Freeze the PhonemeDF-trained model, preprocessing, aggregation, calibration and threshold; evaluate on the eligible English MLAAD-tiny set. Search for duplicate/source overlap across corpora and report generator overlap. Cross-dataset is not automatically unseen-generator, and neither proves that a pretrained encoder never encountered related source speech.

Protocol D: controlled corruption

Make compressed/noisy versions of final-test recordings after the split. Link every derivative to its original and apply identical transformation settings to real and TTS files. Evaluate paired changes without training or threshold adjustment. Degraded copies are not extra independent test subjects.

PHASE 5 · WEEKS 2–3

Preprocess and engineer four representations

A shared waveform contract

Start with mono float32 at 16,000 samples/second. Use four-second crops (64,000 samples) as the initial training unit. Keep the original recording as the evaluation unit. Sample one or a fixed number of crops per recording per epoch to prevent long recordings from dominating. Use deterministic windows at validation and test time.

Proposed short-input policy: flag recordings with less than one second of usable speech as insufficient, pending validation of that threshold. For one-to-four-second inputs, retain true length and right-pad only where required. Avoid repeating audio to fill the crop. For long audio, use deterministic windows with at most two-second overlap and cap app duration to a documented limit, such as 60 seconds. Save a chunk map with start/end times and valid lengths.

For evaluation, use the same chunk boundaries for all four models. Initially average chunk probabilities to one recording score; choose any alternative aggregation using development data only. A partially synthetic recording can be diluted by averaging, so do not claim reliable splice localization from this design.

Logistic Regression features

Compute statistics only over valid audio frames. Keep energy and silence features flagged as potential shortcuts and compare with/without them. Add pitch/voicing only if you can reliably handle unvoiced frames; impute train-derived values and include a validity flag. More features are not automatically better. Record the exact order of feature names so app inference matches training.

RNN features

Use a power mel spectrogram and a documented log transform with an epsilon floor. A suggested starting FFT length is 512 samples with a 400-sample window and 160-sample hop. Fit per-mel-bin mean/std over valid training frames. Apply those statistics unchanged to validation/test. Padding should be masked and excluded from normalization statistics, recurrent computation where possible, and pooling.

Pretrained model inputs

WavLM-Base-Plus expects 16 kHz speech. Use its feature extractor for waveform normalization rather than adding an unrelated normalization chain. [4] AST’s documented default extractor uses 128 mel bins, 1,024 time frames, AudioSet normalization, and pad/truncate handling. Use that matched extractor first. A four-second crop still occupies its fixed feature grid; shortening the waveform alone does not necessarily shorten AST’s attention sequence or memory cost. [6]

Keep AST’s checkpoint input grid at first. A shorter grid is an optional engineering experiment requiring compatible positional embeddings, model configuration and extractor settings. Do not casually set a new max_length and ignore weight-shape mismatches. If you compute new normalization statistics, use training data only and save them alongside the model.

Augmentation policy

First obtain clean baselines. Then compare no augmentation against light, label-independent noise, gain and compression augmentation. Apply transformations to training only, with the same distributions across classes. Do not use voice conversion, pitch shifting or strong time stretching as generic “safe” augmentations for a synthesis detector. Avoid combining many transformations until each has evidence of benefit.

Cache keys should include audio checksum, crop coordinates, preprocessing version, feature settings, checkpoint revision and split version. Frozen pooled WavLM embeddings can be cached; online waveform augmentation requires fresh embeddings or explicitly cached augmented views. A cached clean embedding cannot simulate arbitrary acoustic augmentation.

PHASE 6 · WEEK 3

Train Logistic Regression

Purpose: establish a real baseline before spending GPU time. Train on handcrafted crop features; score and aggregate at recording level. If every recording contributes different numbers of crops, weight or sample to avoid overrepresenting long recordings.

Small, meaningful tuning grid

Try C ∈ {0.01, 0.1, 1, 10} and compare unweighted versus balanced class weights. Select using your declared validation objective. Do not apply SMOTE to raw audio or automatically combine oversampling with class weights; either can change the effective training prior and distort probability scores.

Use the same feature extraction for every candidate. When using cross-validation, fit preprocessing inside each training fold and keep source groups intact. Save coefficients with their standardized feature names; correlated features limit causal interpretation.

Checks before progressing

Compare with majority-class and random-score references. If accuracy is extremely high immediately, audit metadata shortcuts and duplicates before celebrating. If the model cannot fit a small training subset, inspect labels, features and aggregation. Record failure cases: quiet genuine speech, short clips, one specific generator, or source-specific recording conditions.

Deliverables: serialized pipeline, feature specification, validation predictions, chosen C, comparison against the untuned baseline, coefficient plot, and a short error-analysis note. Keep final-test evaluation sealed until the model/threshold lock.

PHASE 7 · WEEK 4

Train the bidirectional GRU

The RNN experiment preserves temporal information lost by MFCC summary statistics. Begin with a two-layer BiGRU, hidden size 128 per direction, dropout 0.3, masked mean pooling, and a two-output classifier. Use BiLSTM only as an optional comparison after the GRU works.

# Architecture sketch: x is [B, T, 64], lengths counts valid frames.
import torch
from torch import nn
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

class BiGRUDetector(nn.Module):
    def __init__(self):
        super().__init__()
        self.gru = nn.GRU(64, 128, num_layers=2, batch_first=True,
                          bidirectional=True, dropout=0.3)
        self.head = nn.Sequential(nn.Dropout(0.3), nn.Linear(256, 2))

    def forward(self, x, lengths):
        packed = pack_padded_sequence(x, lengths.cpu(),
                                      batch_first=True, enforce_sorted=False)
        packed_h, _ = self.gru(packed)
        h, _ = pad_packed_sequence(packed_h, batch_first=True)
        mask = torch.arange(h.size(1), device=h.device)[None, :] < lengths.to(h.device)[:, None]
        pooled = (h * mask.unsqueeze(-1)).sum(1) / mask.sum(1, keepdim=True).clamp_min(1)
        return self.head(pooled)  # logits, not softmax probabilities

Packing prevents padded timesteps from contaminating recurrent states, especially the backward direction. Pooling masks alone do not prevent that contamination. Ensure every length is positive and expressed in feature frames, not waveform samples. This is a starter architecture to integrate and test in your locked environment, not a complete training program. [15]

PHASE 8 · WEEK 5

Train a head over frozen WavLM

Load microsoft/wavlm-base-plus at a recorded revision and freeze its backbone. Put the frozen encoder in evaluation mode and use inference/no-gradient extraction. Frozen weights alone do not disable dropout. Train a small head on pooled embeddings.

WavLM uses a convolutional front end and Transformer encoder for speech representations; it is not a ready-made TTS detector. Your supervised head supplies the binary task. [5]

Recommended first workflow

  1. Use the shared waveform/crop contract and the checkpoint feature extractor.
  2. Extract the final hidden layer for each crop. Start with individual crops or equal-valid-length batches to simplify padding behavior.
  3. For variable lengths, map valid waveform lengths to hidden-frame lengths using the encoder’s convolutional stride/kernel rules. A 64,000-sample waveform mask is not a hidden-state mask.
  4. Compute valid-frame mean pooling; optionally compare mean plus standard deviation. Persist the exact pooling recipe.
  5. Train Linear(D,128) → GELU → Dropout(0.2) → Linear(128,2) using AdamW around 1e-3 and validation early stopping.
  6. Cache pooled embeddings by crop and checkpoint revision. Save extraction cost separately from head-training cost.

Check the processor/model’s documented attention-mask behavior for the pinned version. Independently ensure padded frames do not contribute to your pooling. Confirm a crop produces the same embedding alone and in a batch to a practical floating-point tolerance. Use identical waveform normalization at training and inference.

Optional ablation

After the frozen run is complete, fine-tune the last one or two Transformer blocks at a smaller backbone learning rate, perhaps 1e-5, while retaining the larger head rate. This is a new experiment with its own checkpoint and compute budget. Frozen embedding caches cannot be reused as if they represented the updated encoder.

Interpretation: strong transfer supports the usefulness of speech pretraining for this setup. It does not prove the encoder was never exposed to related corpora: the model card describes Libri-Light, GigaSpeech and VoxPopuli pretraining. Record possible source-domain overlap as a limitation rather than claiming absolute pretraining independence. [4]

PHASE 9 · WEEKS 5–6

Fine-tune the Audio Spectrogram Transformer

Use MIT/ast-finetuned-audioset-10-10-0.4593 as the initialization. The published checkpoint is an approximately 86.6-million-parameter AudioSet classifier, not a TTS detector. Replace its task head and learn from your verified labels. [7]

Three controlled stages

  1. Forward-pass check: load matched processor/model, replace the output head with two classes, verify finite logits with shape [B,2], and inspect all mismatched-weight warnings.
  2. Head warm-up: freeze the backbone, keep it in evaluation mode, and train the new head for one to three epochs. Evaluate this frozen-AST result as a useful ablation.
  3. Partial adaptation: unfreeze the last two Transformer blocks, the final normalization as appropriate, and the head. If validation supports it and compute permits, compare four blocks. Keep frozen blocks deterministic. Rebuild optimizer parameter groups when trainable parameters change.

Memory and training pitfalls

Freezing layers saves parameter-gradient/optimizer storage but does not eliminate every activation cost. A short waveform padded to the default grid still creates the default patch sequence. Lower the microbatch first, then increase accumulation. Activation checkpointing and shorter grids are optional optimizations that must be tested, not assumed to work identically across versions.

Use integer 0/1 targets with cross-entropy. Do not copy AudioSet multi-label sigmoid/BCE training unchanged into this mutually exclusive two-class task. Verify trainable parameter names, optimizer membership and nonzero gradients. Restore frozen modules to evaluation mode after any blanket model.train() call.

Follow the original AST repository for architecture details and adaptation examples, but do not copy its reported benchmark accuracy into EchoProof. Those results concern different datasets and tasks. [8]

Training-loop responsibilities

  1. Seed Python, NumPy, PyTorch and data-loader workers; record deterministic settings and their limitations.
  2. Call train/eval modes deliberately, preserving frozen-module behavior.
  3. Zero gradients, compute logits/loss, backpropagate, clip if configured, step optimizer and scheduler.
  4. With accumulation, scale loss and handle the final partial accumulation group correctly.
  5. Evaluate deterministic validation chunks without gradient tracking; aggregate to recordings before model selection.
  6. Save best weights plus optimizer, scheduler, scaler, epoch and RNG state for resume; save inference-only weights separately.

Calibration and operating thresholds

A softmax output is not automatically reliable confidence. Fit temperature scaling for neural logits, or an appropriate sigmoid calibrator for classifier scores, on held-out calibration data. Reliability plots, log loss and Brier score help assess calibration. Calibration data must be disjoint from model fitting; calibration is also distribution-dependent. [11]

For this project, calibrate recording-level scores after the fixed chunk aggregation: for example, clip the aggregated score away from 0/1, convert it to a logit, and fit a scalar sigmoid/temperature mapping. If instead calibrating chunks, validate the final recording probabilities separately. State which method was used.

Use a separate operating-validation subset to choose the threshold, for example maximizing macro F1 or satisfying a predeclared genuine false-positive constraint. A suggested 5% validation FPR limit is a design target, not a guaranteed deployment bound; report the genuine sample count and uncertainty. Do not choose a test-specific threshold.

The interface may abstain on scores in a validation-selected uncertainty interval, but a middle score does not detect all out-of-distribution inputs. Always report the binary detector’s full-set metrics. For the abstaining interface, additionally report coverage and error among accepted cases so rejection cannot hide poor performance.

EER is a benchmark statistic, not your deployed threshold

Let FNR = 1 − TPR. EER is found where FPR = FNR on the test ROC sweep. That sweep uses test labels to summarize ranking; it does not authorize deploying the test EER threshold. Report operational FPR/FNR separately at the locked validation threshold. Interpolation conventions can differ, so document yours. [12]

import numpy as np
from sklearn.metrics import roc_curve

def interpolated_eer(y_true, tts_score):
    y_true = np.asarray(y_true)
    tts_score = np.asarray(tts_score, dtype=float)
    if set(np.unique(y_true)) != {0, 1}:
        raise ValueError("EER needs genuine and TTS recordings")
    if not np.isfinite(tts_score).all():
        raise ValueError("Scores must be finite")
    fpr, tpr, _ = roc_curve(y_true, tts_score, pos_label=1,
                           drop_intermediate=False)
    fnr = 1 - tpr
    difference = fpr - fnr
    j = np.flatnonzero(difference >= 0)[0]
    if j == 0:
        return float((fpr[0] + fnr[0]) / 2)
    weight = -difference[j-1] / (difference[j] - difference[j-1])
    return float(fpr[j-1] + weight * (fpr[j] - fpr[j-1]))
# Returns a fraction: 0.05 means 5%. This is linear ROC interpolation.

Uncertainty and fair comparisons

Bootstrap at the independent source-speaker or utterance-group level, retaining all related recordings and paired corruptions together. Use the same resampled groups for model differences.
